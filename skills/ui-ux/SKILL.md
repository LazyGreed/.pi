# UI/UX

Design from user tasks and product identity, not generic SaaS patterns or image-gallery aesthetics. Establish primary outcome, decision points, task sequence, contexts, input devices, and failure/recovery behavior. Define hierarchy, clear actions, and states before decoration. Respect platform idioms and user control.

Visual expression should derive from the product, with deliberate typography, contrast, density, rhythm, composition, and meaningful motion. Avoid automatic bento grids, glowing gradients, fake terminal screenshots, repetitive hero templates, and unnecessary cards. Taste is a decision process, not a preset stylesheet.

Always account for keyboard/focus, accessibility, reduced motion, error/empty/loading/stale states, permissions, localization/content extremes, and performance constraints when applicable. Prototype interactions, not just the happy-path screenshot.

Read only relevant references: `interaction.md` (all UI), `visual-taste.md` (art direction), `platforms.md` (desktop/web/mobile/TUI), `accessibility.md` (inclusive input and motion). Landing pages are a task-specific case of this skill, not a separate default skill.
